# S6E9 榜首级 Trick 研究策略

更新时间：2026-09-10。本文记录“怎样接近榜首方案”的可验证结论，不把未知的私人提交文件猜成事实，也不消耗 Kaggle 提交次数。

> 后续自训练实验与验证修正在 [self_model_progress_2026-09-10.md](internal/self_model_progress_2026-09-10.md)：新增十折 probit XGBoost OOF 0.9462762；公式残差 TabM OOF 0.9459551，且对自训练组合有增益；最终纯自训练探索性候选 OOF 0.9463525。因此下文对整个神经网络架构家族的排除结论应缩小到当时实际检查过的配置。支持规则必须验证整个折内发现流程，随机重分折仅属稳定性检查。

## 先定义差距

目前公开榜首 Chris Deotte 的 Public AUC 是 `0.94672`。我们本地最好的完整 OOF 是 `0.9463902775`，账号已验证的最好 Public AUC 是 `0.94643`。两者差距只有约 `0.00029`，但这已经明显大于同一模型家族常见的微小换参波动。

这个差距不能直接解释成“榜首用了一个更大的模型”。公开的 `cdeotte/fable-5-1-xgb-starter` 主要展示原始数据的公式和 XGBoost 示例：它的公开 OOF 约为 `0.94198`，不能解释 `0.94672`。原始数据生成公式本身也已经在我们的特征空间中被树模型重新学到，单独加入公式没有突破。因此，榜首最终提交很可能包含未公开的实验、另一套数据生成器视图，或一个我们无法取得的内部提交文件。现有公开资料不足以证明具体是哪一种。

## 已经确认的主 Trick

真正有效的路线是识别合成器留下的指纹，再把指纹直接交给模型。

1. `Annual_Income_USD` 不能只当作连续收入。相同的 exact value 在不同取值之间有明显的非单调购买率差异。训练集有约 `13,214` 个收入值，很多值在合成数据中被重复采样；`30,000` 是一个巨大的 mode collapse，`170,537` 以上在训练集里全部为正例，`31,004--41,970` 的已观测区域几乎全部为负例。
2. `Daily_Commute_km` 有一个非常大的 `5.0` km spike，但它只有约 805 个取值，树模型可以直接找到，收益远小于收入的高基数 lookup。
3. 对收入、通勤和年龄做严格 nested target encoding，把每个值的训练折 target rate 作为特征。编码器必须在每个 outer training fold 内再次 inner cross-fit，验证折标签不能参与映射。
4. 对原始 10,000 行做值频率、source lift、novelty 和重复采样审计。`train+test` 的频率是无标签信息，可以安全使用；原始数据标签只能作为单独的诊断或严格外层训练特征。
5. 低基数变量的硬规则只能作为已验证边界的检查。把三条手写 flag 加到已有树模型的收益约为 `0.00002`，不能解释榜首差距；高基数收入值的完整 lookup 才是大收益来源。

这组方法的核心不是“让模型更复杂”，而是让模型看到它原本无法用少量 range split 表达的 value identity。一个树若想逐个隔离数千个收入值，需要消耗大量切分；target rate 和 frequency 把这个问题变成了一列数。

## 已排除的假方向

以下路线已经有本地 OOF 或公开复盘证据，不应再作为主攻方向：

- 普通 XGBoost、LightGBM、CatBoost 的深度、学习率和 seed 扫描，预测高度相关，增益在噪声附近。
- 只加入公式分数、普通 pair target encoding、PCA、kNN 原始数据匹配、完整重复行匹配、ID 或行顺序。
- 将 exact income/commute 当作未正则化的原生高基数类别。模型会过早记忆，反而损失 additive 形状。
- 大量同源模型的 stacking、hill climbing 和 rank averaging。只有在新成员既强又有独立误差时，ensemble 才会有可靠收益。
- 直接把原始 10,000 行追加进训练集。比赛数据主要是按边际或合成分布重新采样，无法恢复源行。
- 普通 pseudo-labeling。高置信筛选在不平衡数据上主要筛出负例，会把伪标签先验压到远低于真实正例率。

## 2026-09-10 新验证

### 训练频率和测试频率分离

新增探针 [train_frequency_views.py](../artifacts/experimental/train_frequency_views.py)，对十个字段加入：

- `train_count(value)`、`test_count(value)`；
- 两批次的相对频率；
- `log(test_count + 1) - log(train_count + 1)`；
- 合并频率。

这些特征完全不读取标签。完整五折 XGBoost OOF 为 `0.9460031603`，低于 canonical `xgb_nested_v1` 的 `0.9460556450`，因此“同一 value 在 train/test 的批次比例”暂时不是新的主信号。它仍然保留为生成器审计特征，不能单独拿来提交。

### 保持正例比例的 pseudo-labeling

在 outer fold 0 中，先用只看 outer training fold 的模型预测测试集，再从测试预测的两端挑选伪标签，并让伪标签正例比例保持约 `17.46%`：

| 伪标签总数 | 伪正例数 | 验证 AUC | 相对未加伪标签 |
| ---: | ---: | ---: | ---: |
| 0 | 0 | `0.9451138711` | 基准 |
| 20,000 | 3,493 | `0.9450239635` | `-0.0000899077` |
| 50,000 | 8,732 | `0.9446808689` | `-0.0004330023` |
| 100,000 | 17,465 | `0.9439970794` | `-0.0011167917` |

这不是完整五折结论，但方向已经很明确：硬伪标签把模型自己的错误当成新监督，规模越大损失越大。若以后重开这条路线，只应测试 soft-label、温度校准和真正的分层置信门槛，并要求至少完整五折通过后才能考虑提交。

## 真正可能接近榜首的三条路

### 1. 继续做生成器逆向，而不是继续调树

把原始数据当作分布参考，不把它当作可直接匹配的源表。对每个高基数数值计算：

- 原始支持中的 exact match、最近邻距离、前后支持间距；
- empirical quantile、局部 source density、competition/source share；
- 合成值、剪裁值和 mode collapse 的分段标识；
- 这些量与 exact value target rate 的条件关系。

关键判据是：新特征必须在 outer training fold 内发现，在未参与发现的 validation fold 上带来稳定 paired gain。只在全量 OOF 上挑选“全负区间”会造成验证泄漏，之前已出现过虚假的 `+0.0003` 级提升。

### 2. 寻找第二个接近 parity 的独立表示

当前最强成员都是同一类 additive GBDT，相关性通常超过 `0.99`。真正有价值的第二成员需要同时满足：

- 单模 OOF 接近 `0.9463`，不能只靠低相关性；
- 与主模型的误差相关性明显更低；
- 在固定五折上每折方向基本一致；
- 不是在同一份 OOF 上反复调权重得到的偶然组合。

可优先试的是“生成器支持密度 + additive target rate”的独立模型，例如正则化 GAM、分段线性模型或只在 income/commute support space 上工作的模型。TabM、MLP、TabICL、NODE、ModernNCA 和 TabTransformer 已经证明，换架构本身没有形成强且低相关的成员。

### 3. 若重开半监督，必须 class-balanced 且 soft

普通 confidence gate 的失败机制已经清楚：在正例率 `17.46%` 的数据里，按绝对置信度保留的样本几乎都是负例。可行的研究协议应是：

1. 每个 outer fold 只用 outer training fold 拟合教师模型；
2. 在测试样本上按预测分位数分层，分别取正、负伪标签；
3. 优先使用教师概率作为 soft label，而不是把极端值硬写成 0/1；
4. 伪标签权重从很小值开始，并与真实标签权重分开；
5. 完整五折 paired OOF 超过预设门槛后才生成本地候选。

目前的 20k/50k/100k 硬标签试验均为负，所以上述路线只是“剩余可证伪假设”，不是已验证 trick。

## 提交纪律

AUC 只看排序。候选选择应按以下顺序：

1. 先保存每个候选的 OOF、test prediction、每折分数、配置和 SHA256。
2. 用固定折做 paired 比较，并检查是否超过当前实验噪声门槛。
3. 对外部公开文件只记录其真实 Public 证据，不把它当作本地 OOF。
4. 新候选没有独立证据时不消耗提交次数；榜首公开分数不能反推出其隐藏代码。
5. 只有在用户明确授权后，才用 `scripts/submit_checked.py` 上传一个预先审计过的文件。

当前结论是：我们已经掌握了这道题最重要、可复制的 generator-fingerprint trick；从 `0.94643` 到 `0.94672` 的剩余差距，公开资料没有给出可直接复制的答案。下一步的价值在于验证新的生成器支持表示，或发现榜首使用的独立高质量外部成员，而不是继续堆叠同质模型。
